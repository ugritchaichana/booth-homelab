# 0050. Allow anonymous cache reads and gate writes with one writer credential

- Status: Accepted
- Date: 2026-10-07
- Deciders: operator
- Decision log: D78 in docs/platform/requirements.md

## Context

Runner jobs must read the cache on every build, including jobs triggered by pull requests from forks. The content is build output of public repositories. The cache is only reachable from the runner vnet: the guest firewall admits tcp/8080 from that subnet and tcp/22 from the gateway (security group `cache-ingress`, ADR 0027 pattern).

## Options considered

1. Credentials for reads and writes — every runner job would hold a secret, and a pull-request job can print whatever it holds.
2. Anonymous reads and writes — nothing to leak, but any job on the vnet could poison the cache.
3. Anonymous reads, one writer credential — jobs that must not write never hold anything.

## Decision

Option 3, with bazel-remote `--allow_unauthenticated_reads` and an htpasswd file holding one user, `ci-writer` (ADR 0048).

- The password is generated by `scripts/iac/cache-writer-secret.sh`, stored in `iac/secrets/hosts/pve01-cache.sops.yaml` (key `writer_password`, one writer: that script) and set as the secret `CACHE_WRITER_PASSWORD` of the GitHub environment `cache-writer`. Ansible reads it from SOPS and writes only a bcrypt hash on the container, with the password passed on stdin and the task under `no_log`.
- Jobs for pull requests never receive the credential: only a job that declares `environment: cache-writer` can read the secret.
- Reads are anonymous by design. A caller on the vnet can read any entry whose hash it knows; the hashes are of public build output.

## Rationale and trade-offs

- The environment's branch policy (default branch only) is an owner setting and is currently unset. Read 2026-10-07: `deployment_branch_policy: null` for environment `cache-writer`. Until the owner sets it, a workflow on any branch that names the environment can read the credential. NAMED GAP, not closed by this change; the PR-job rule above holds only for workflows that do not name the environment.
- One credential means one rotation: `scripts/iac/cache-writer-secret.sh --rotate`, then converge the role, which rewrites the hash and restarts the service.
- bazel-remote verifies the sha256 of every content PUT (ADR 0048), so the credential cannot plant content under a wrong address; it can still fill the cache, which is bounded by the LRU size limit.
- The traffic is plain HTTP on the private vnet; Basic auth credentials are visible to anything that can sniff that segment. Accepted for a single-host lab bridge; revisit before the cache leaves the host.
